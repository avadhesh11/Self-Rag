# EvoRAG Blind Evaluation & Prediction Freeze Protocol (Task 9A.1)

This document specifies the blind evaluation methodology, prediction freeze mechanics, and execution procedures for the **32 held-out question archive** evaluated across Normal RAG, Self-RAG, and EvoRAG.

---

## 1. Executive Summary & Blind Evaluation Objective

The goal of Task 9A.1 is to establish a rigorous, tamper-proof, and reproducible blind evaluation protocol to assess:
1. **Normal RAG** (baseline retrieve-then-generate).
2. **Self-RAG** (adaptive multi-segment reflection-token generation).
3. **EvoRAG** (hybrid experience-learning with three-path routing).

### Core Principles
* **Zero Contamination**: The 32 held-out test questions are strictly decoupled from the answer key and evaluation labels.
* **No Parametric / Memory Leakage**: The evaluation runner explicitly prohibits approving or persisting held-out questions into SQLite/FAISS Experience Memory (`approve_and_save` is never invoked during evaluation).
* **Identical Corpus Baseline**: All three systems query the exact same document corpus (`index/dbms_sql_v1/`, 232 passage chunks across 15 DBMS/PostgreSQL 18 documents).
* **Prediction Freeze**: Generated answers, citations, retrieved chunks, reflection traces, and latencies are frozen in structured JSONL and CSV formats before any scoring occurs.

## 4. Prediction Schema & Outputs

Predictions are frozen into a dedicated output directory (e.g., `evaluation/predictions/frozen/`).

### Standardized CSV Schema (`predictions_<timestamp>.csv`)
Conforms directly to the evaluator's template:
1. `question_id`: Held-out ID (e.g. `DBMS-EVAL-0041`).
2. `system`: System evaluated (`normal_rag`, `self_rag`, or `evorag`).
3. `predicted_answer`: Complete answer string generated by the system.
4. `cited_source_ids`: Semicolon-delimited source filenames (e.g. `08_database_storage_pages_and_buffer_management.pdf`).
5. `cited_pages`: Semicolon-delimited page numbers (e.g. `1;2`).
6. `retrieved_chunk_ids`: Semicolon-delimited chunk IDs.
7. `retrieved_passage_count`: Number of passages retrieved.
8. `retrieval_segment_count`: Number of Self-RAG retrieval segments (1 for Normal RAG, 0 for direct reuse).
9. `llm_call_count`: Approximate LLM forward passes or tree-search calls.
10. `latency_ms`: Total end-to-end wall-clock latency in milliseconds.
11. `memory_candidate_found`: Boolean flag (true if Experience Memory found any semantic candidates).
12. `memory_hit`: Boolean flag (true if Experience Memory matched and passed validation).
13. `memory_reuse`: Boolean flag (true if Path A direct reuse occurred).
14. `fallback_reason`: Description of fallback if memory candidate was rejected.

### Detailed JSONL Schema (`predictions_<timestamp>.jsonl`)
In addition to the CSV columns, records full retrieved passage dicts, separate retrieval and generation latency (where available), routing mode, configuration metadata, and multi-segment Self-RAG reflection tokens (`[Relevant]`, `[Fully supported]`, `[Utility:N]`).

## 5. Blindness & Reproducibility Safeguards

1. **Answer-Key Independence**: The loader inspects input JSONL records and raises a `ValueError` if any ground truth fields (`expected_answer`, `ground_truth`, `label`, etc.) are present.
2. **Read-Only Guarantee**: Automated test `test_question_archive_is_not_modified_during_run` verifies that the source JSONL byte contents and file hashes remain unaltered during the evaluation.
3. **No Memory Contamination**: The evaluation runner never calls `controller.approve_and_save()`. Experiences can only be added to Experience Memory through verified, separate training/onboarding workflows.
4. **Resilience**: Any exception raised during execution (e.g. API rate limit or context length) is caught and recorded in the `error` field of the row; no questions are dropped.

```bash
  --questions EvoRAG_Blind_Test_Questions/held_out_test_questions_only.jsonl \
  --out-dir evaluation/predictions/frozen \
  --index index/dbms_sql_v1 \
  --model models/selfrag_llama2_7b.Q4_K_M.gguf \
  --k 5 \
  --max-segments 3
```

### Hardware & Resource Bounds
* **RAM**: 16 GB+ system memory.
* **Apple Silicon**: Metal GPU acceleration (`n_gpu_layers=-1` in `llama-cpp-python`).
* **Linux / NVIDIA**: 14 GB+ VRAM for vLLM or cuBLAS.
* **Normal RAG**: Requires `GEMINI_API_KEY` in environment.

## 7. Metrics Prepared for Downstream Scoring

Once predictions are frozen, downstream evaluation against the sealed answer key can score:
* **Answer Correctness**: Strict token F1, ROUGE-L, and Semantic LLM-as-a-judge accuracy.
* **Faithfulness**: Grounding ratio of claims in `retrieved_passages`.
* **Citation Correctness**: Precision and recall of `cited_source_ids` and `cited_pages`.
* **Experience Memory Effectiveness**:
  * Memory hit rate: $\frac{\text{Hits}}{\text{Total Questions}}$.
  * Direct reuse latency reduction: Comparing Path A latency vs. full Self-RAG generation latency.
* **Latency Profile**: Average, Median (P50), and P95 latency in milliseconds.
